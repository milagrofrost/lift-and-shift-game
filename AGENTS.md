# Contributor and AI assistant guidance

## Purpose and design philosophy

Lift & Shift teaches cloud migration alongside BAU: email, tickets, maintenance, compliance, service recovery, security, and financial pressure. The player starts overwhelmed and progressively builds systems that make routine work manageable.

- Mature automation should be a net positive. Early tools can be unreliable; upgrades should visibly reduce toil and intervention.
- Keep meaningful tension without making recovery an uncontrollable cascade of failures.
- Preserve humor and IT satire, but make cause and effect understandable.
- Routine maintenance is not an emergency. Distinguish healthy, covered, maintenance-needed, and failed states visually.
- Do not invent mechanics based on a literal example number. Preserve existing tuning unless the requested change includes rebalancing.

## Repository and branch handling

- Inspect Git status, branch, and applicable instructions before editing. Preserve unrelated user changes.
- `lift-and-shift.html` contains the game. No build system is required, but Cloudflare's build command copies a fixed list of root files: a new file the game loads from the root must be added to it (see "What Cloudflare publishes" in `.github/README.md`). `functions/` holds dependency-free Cloudflare Pages Functions for shared report links and older versions (`/v/`).
- Gameplay revisions are merged into `main`. Cloudflare Pages deploys `main` to https://las.milagrofrost.com. Use feature branches and pull requests; `main` is protected (pull request plus four green CI checks), and merging publishes the site.
- Workflows: `.github/README.md` explains every GitHub workflow, the protection on `main` and the required check names. Any change under `.github/workflows/` must update it in the same pull request (CI enforces this). Renaming a CI job also means updating the ruleset's required checks.
- The design direction below describes accepted behavior, including feature-branch work. Inspect the current branch before claiming it is implemented.
- Do not merge branches, rewrite history, publish releases, or change repository visibility without authorization.
- Keep local machine configuration, credentials, temporary scripts, and personal paths out of commits. `.claude/` is local configuration, not part of the published game.

## Accepted gameplay direction

### Patch cycles

- Normal servers have randomly assigned 42–65-second base cycles; discovered hidden servers originally use 40 seconds. Preserve these lengths unless explicitly asked otherwise.
- A successful patch at any point covers the **current cycle**. It does not reset the timer, add a second timer, bank extra cycles, or shorten future cycles.
- A covered cycle keeps counting down internally. Show a green draining bar and a checkmark / COVERED label, with no numeric countdown or green warning circle.
- When a covered cycle ends, reset to a fresh, uncovered cycle without an audit penalty. The normal countdown resumes.
- An uncovered cycle that expires fails its audit. Yellow and then red circles communicate approaching risk only while uncovered.
- Reject redundant patches on covered servers. Helpers must honor the same coverage state as the player.

### Completion and accounting

- Any outage or active breach blocks client completion. Developing leaks and warning states do not by themselves block completion.
- Check failure conditions before awarding completion.
- Failed cutovers must not award decommissioning savings or remove future license obligations. Successful migration rewards apply once per server.
- A license counts down only while its server runs on its rack. It pauses while carried or in the pipeline and resumes on return. A blue-green original stays on its rack, so it keeps counting and can still renew.
- Rollback counts as service restoration. Player, bot, and pipeline migrations must use consistent delivery statistics.

### Escalations, recovery, and freezes

- Ticket escalations **do cause server fires**. Do not replace this with random infrastructure fires or penalties alone.
- During any outage or active breach, slow escalation pressure considerably; the feature branch uses one-quarter normal escalation speed. Escalations still happen outside explicit freezes.
- The ticket queue and the inbox hold only what their bars show (5 slots, plus retrospective slots). A full queue takes nothing new, so there is never a hidden backlog; a full ticket queue still escalates and a full inbox still sends VPs until it is worked down. Vendor spam is not capped, and an AI agent mistake can push the inbox past the cap by its two angry replies.
- Each escalation needs 12 seconds of full queue, and a dip below full does not reset that wait. While any server is burning, escalation runs at half speed; an outage or active breach takes precedence at one-quarter speed.
- Escalations retain server identity through pickup, relocation, pipeline transit, failed cutover, and rollback. Wait at the last rack while the target is absent; reacquire its actual rack when it returns. Do not silently retarget a different server or discard the escalation on pickup.
- Successful migration may retire that server's escalation.
- Managers provide bounded automatic freezes for critical incidents; all tiers help, higher tiers provide more protection. Explicit freezes pause users, arrivals, queue pressure, fire growth/spread, and breach spread while recovery continues.
- Downtime and active breach damage still count during freezes. A freeze contains chaos; it does not fix the incident.
- Prevent repeated automatic retriggering within one continuous incident. Respect cooldowns.
- Emergency freeze is a single carried charge, repurchasable after use. Extend existing protection with a cap rather than wasting the charge or stacking indefinitely.
- No adrenaline system has been requested.
- Red-alert slow-mo: during a red alert, hunting VPs approach at 0.6× on Easy and 0.85× on Normal (none on Hard or Hardcore), easing in and out. Only VPs slow: other users, NPCs, timers, hazards and the player's repairs run at normal speed. A heartbeat fades in slow and quickens/fades out as it ends; the song drops its bass and kick under it, and the room's edges darken.
- Badge readers: each server-room door has one on the hallway side. Entering plays a faint ting and turns it green for 1 second; leaving turns it green silently; the player, the manager and VPs badge in normally. Temps badge in too (ting). Bots and the AI agent don't use it. One temp in ten is a dud, split evenly: 5% snack hoarders and 5% never onboarded (badge denied every 3 s at the on-prem door, no work, quit after 12 s). Badge Access Audit (upgrade) only delays hunting VPs: they stand beside the door, are denied 3 times 3 seconds apart, pause, call Bob (about 4.5 s), then have access and follow you as normal until they catch you or give up. A VP can piggyback through while the door is green, including when someone walks out past them. The manager keeps access.

### AI Agent foundations

- The AI Agent amplifies existing practices. With no foundations for a job, it keeps its base level odds; each relevant upgrade improves that job only (patching: Patch Bot, Runbooks, Observability). Foundations shift results toward success; they do not add a penalty or stop tokens being billed.
- Patch Bot walks faster at each level (85/110/140) and the AI Agent moves faster at each level (300/340/380/420); level 1 keeps the original pace.
- Level 1 only touches bronze servers, level 2 adds silver, level 3 adds gold; tickets and email are open at every level. Baselines are 50%, 80% and 90% right, and never certain.
- A Patch Bot automation error draws the agent ahead of tickets and email, within its server tiers, using its normal patching odds.
- When the agent breaks something it stays, apologizes, and makes one billed repair attempt. A failed repair leaves the problem to the player and never causes further damage. Damage already charged stays charged. Some damage is beyond it, and the apology is still billed: level 1 can't bring back a server it knocked offline, and below level 3 it can't put out a fire its escalation started ("Sorry, I can't fix that."; no remote firefighting). Level 3+ walks to the server and, on a successful repair roll, puts the fire out with its digital extinguisher at its firefighting rate rather than instantly.
- Priorities: at level 4, incidents first (breaches, outages, fires, failed cutovers). Level 3+ then repairs a jammed pipeline. Then the email or ticket queue, whichever is fuller, once either is at least half full. Below that it looks for fixes: leaks, automation errors, at-risk patches, unknown racks (level 2+), routine patches. Then whatever is left in the queues.
- Level 2+ investigates unknown racks start to finish (any tier, billed once, always succeeds), unlike a temp. Level 3+ follows an escalation it caused to its target server (keeping server identity) and repairs there, including an outage that escalation caused.
- CI/CD pipeline jams: every send (player or Mover Bot) rolls once, and 15–20% of them jam partway across the hallway (`pipeJob`, `jammed`). The lane stops with its server stuck on the belt; it is still "in the pipeline" for every rule (migration burn unless a blue-green copy, paused license, escalation identity, canceled if the original goes offline). Repair: stand anywhere on that conveyor and hold E (free, 2.5 s, progress kept; touch word UNJAM), a skilled human action. A level 3+ AI agent repairs it too (hands-on, billed once, no right/wrong roll), after level 4's incidents and before the queues; below level 3 it leaves it to you. Temps, Patch Bot and Mover Bot never repair it, freezes don't, and no upgrade changes the odds. Each lane jams independently; the Mover Bot waits for a free lane. Jam alarm (`tickJamAlarm`, `jamBuzz`): a low square-wave factory buzzer, three buzzes, 0.9 s after a jam and then every 4 s while any lane is jammed; one alarm for any number of jams. Quiet while anyone (you or the agent) is repairing a jam and during a red alert (the siren wins); it resumes within 1.5 s once the quiet ends. Each buzz is a WARN in the DEBUG log. The red lane stays the visual signal, so muted and reduced-motion play lose nothing.
- Level 4 incident response is hands-on work with no right/wrong roll; failed-cutover retries still roll the normal cutover odds. The agent itself never migrates.
- Level 4 swarm (`tickAgent`, `agentClaims`): the agent forks a copy of itself for every job nobody has claimed, one fork every 0.5 s, up to 8 copies at once (`CLONE_MAX`). Each fork bills $0.3k and each copy bills its own attempts at level 4 rates. Copies use the normal priorities but never take a server, lane or queue item another copy holds; each shows its role (INCIDENT, OPS, SECOPS, FINOPS, PIPELINE, SERVICE DESK) and merges back after 1.5 s idle. Below level 4 there is one agent and its behavior is unchanged.
- Level 4 also takes over Patch Bot and Mover Bot (`infected`; never a temp's bot): they turn purple with orbiting AI glitter (still under reduced motion), move 60% faster, work twice as fast, and bill $0.4k per job. Patch Bot uses the agent's level 4 patching odds when they beat its own. Migration still belongs to Mover Bot and the player. Hands-off level 4 clients finish roughly 35–40% sooner at about 50% more AI spend.
- At AI level 4 the player can fire the manager between clients, once per career. The manager's freezes, uptime recovery bonus and email foundation stay (the agent runs them); the walker, chatting, guarding and inspections go, and the manager can't be bought again.

### Uptime recovery

- Outages burn the uptime budget by tier: gold 3/s, silver 1/s, bronze 0.25/s. Bronze and silver outages are survivable; gold is what gets you fired.
- A server shut down for migration (carried or in the pipeline, including stuck on a jammed lane) burns a quarter of its outage rate; each Redefine "Uptime" level removes 20% of that. Blue-green moves burn nothing. Moving servers are drawn as OFF; one you carry is held over your head as a small copy of its rack tile (tier colour and stripe, 🖥️, name) with an OFF badge, or a dashed blue COPY for a blue-green move (`drawCarryTile`), so your avatar stays visible inside the dashed carry ring. The uptime box pulses red slowly during migrations, faster when migration burn is heavy, and very fast during outages.

A manager's server visit is an inspection that takes the server offline half the time. A break sends the manager on a slow walk to the inbox and blocks visits for 45 seconds per career break, capped at 300. Holding E at that server during the inspection cancels it without counting as a break.

It uses no randomness. `wiresnark` (or `tcpdump`) opens WireSnark (`assets/wiresnark.js`, kept as `WS`), a Wireshark-style capture of the floor: the usual columns and colouring rules, a details tree and a hex dump whose ASCII is the snark, a display filter (plain text match) and Start/Stop/Restart. Packets come from what the floor shows: chatter scaled by the machines on screen (known racks, live cloud apps, hallway people, you), a wall of red on outages (RST, retransmissions, ICMP unreachable, 503s), TTL exceeded on fires, exfiltration to 175.45.176.0/22 growing with a visible leak, red SSH on breaches, rsync for migrations (zero window on a jammed lane), ARP/LLDP/NetBIOS for an unknown rack being investigated (never its name or tier), escalations in flight (target redacted), hunting VPs and a full ticket queue. Capture time is game time, so pausing the game pauses it. It has its own random generator. To stay light it keeps only its last 150 packets (`MAX_ROWS`, in the table and in memory), redraws the table 4 times a second (`PAINT_MS`) inside a contained list, and does no work while closed. `git checkout day2` puts the Day 2 prototype on the main menu until reload (the one command that unlocks something; it still never touches `S`). `history` is the previous consultant's "back in my day" commands followed by this page's own (`TTY_HIST`; the cheat never lands there). `cd do_not_delete` is the only other directory (`CWD`, `FILES`): `ls`, `pwd`, `cat` and `rm` follow it, `cd ..`/`cd ~` go home, and `cd` prints nothing when it works. All of this lives outside `S`.
- Read-only Friday: on the player's real Friday (`isFriday`, device clock), `date` says so and the first `play()` of the page load toasts "Read-only Friday!" (`fridayTip`, never in the tutorial). It's an acknowledgement only: nothing about play changes.

### Career and balance

- After two rough clients in a row (5–6 sprint points or at most 2 stars), the retrospective offers "Give me a break" as one of its three options: one small client, sized and paced like the first, in place of that retrospective's action item. The shop after that client always stocks Patch Bot and every upgrade with a base cost of 5 or more that is not owned yet, including the AI Agent once unlocked.
- The four break clients (Crybaby Daycare, Just Bubbles Bar, Training Wheels Warehouse, Participation Trophy Outlet, in that order per break taken) bring their own hallway crowd through `talk` on the client: everyday lines, red-alert shouts and "want a human" shouts (`userLines`, `alertLines`, `humanLines`). Daycare users babble ("Goo goo", "WAH WAH WAH!" in an alert) and are drawn at 72% size with full-size rank labels; the bubble bar speaks only 🫧 (popping 🫧💥 in an alert); Training Wheels users wobble ("Don't let go!"); the trophy outlet is relentlessly encouraging ("How are kids gonna know they're special?!"). Swapping lists keeps the same single random pick, and hunting VPs (ours) always talk like a VP. Sizes are drawing only: hitboxes and hold times don't change.
- Continuous improvement (retrospective option `ci`): offered from the 8th finished non-break client, only with the AI Agent owned or on an old school career, and only with 2+ owned stackable tools not yet maxed. Once it has shown up (`S.ciSeen`) it is in every retrospective until chosen, as long as one tool is left to lock in. The retrospective always has exactly 3 options: "Give me a break" and Continuous improvement take their slots first and what hurt fills the rest. Choosing it asks first ("can't take it back"). Adopting locks in those tools (`S.ciLock`) and reshuffles the current shelf: each shop then holds 2 tools you don't own yet (a break's guaranteed big-ticket shelf still wins) and fills the rest with locked-in tools; a maxed tool leaves the list, and once all are maxed the shop is back to normal.
- Early finish refund: finishing a client ahead of its lease target wins back sprint points lost to unplanned work: +1 at 2 days early, +2 at 4 or more (`earlyBack`, `capBase`, `capNext`). It only refunds what was lost, so it never lifts the sprint past 13 and a clean engagement (already 15) gets nothing. "Give me a break" judges the points before the refund (`cap0`). The Next sprint bar includes it live and says so; the refund shrinking as days pass doesn't flash the bar.
- Coffee (hallway pickup): +15 energy and 4 WIRED seconds in which the player walks and does every hold-E job 30% faster (`WIRED_WORK`). Only the player: bots, temps, the manager and the AI agent are unaffected.
- Big Slice Pizza Co. (and its later phases) throws way more pizza parties: specials arrive 40% sooner and 5 in 8 (4 in 7 with a temp out) are pizza, still one roll each.

- Until the player owns a Patch Bot, the shop always stocks it whenever they have the points to buy it (4). Below that, and for later levels, it uses the normal draw.

- Cloud running costs: on-prem 0.12/s per app; cloud 0.13/s after a plain lift-and-shift. Terraform, Observability and Cloud Auto-Patching cut it 10% each, multiplied. ## Agent change-and-review workflow

Use this sequence for each change, scaled to its scope. Keep notes in the task or PR; do not add a process document for every small edit. This workflow does not authorize merges or publication.

1. **Define success before editing.** State the player-visible outcome (or contributor outcome for documentation/tooling), classify the change as presentation, behavior, balance, or a combination, and identify a few observable acceptance checks. Preserve existing tuning unless rebalancing is requested.
2. **Map the affected paths.** For shared behavior, identify the relevant player, Patch Bot, Mover Bot, manager, temporary worker, AI agent, pipeline, rollback, restore, and client-transition paths. Mark irrelevant paths briefly rather than silently omitting them. Use the implementation and validation requirements below to choose edge cases.
3. **Implement and check consistency.** Make the smallest coherent change. For presentation and interaction, review `DESIGN.md` and affected findings in `docs/design-audit.md`: state meanings, shared components, wording, keyboard/touch controls, and reduced motion. Update affected explanations alongside behavior.
4. **Collect evidence appropriate to the change.** Behavior changes need meaningful deterministic checks; appearance needs real browser observation; input needs actual interaction; motion needs observation over time, including reduced motion. A screenshot cannot establish input or animation correctness. Documentation-only changes need content, reference, and diff review rather than gameplay tests. Run the applicable checks below.
5. **Review the final diff in a separate pass.** Compare the finished change with the acceptance checks. Look for contradictory instructions, unintended tuning or accounting changes, missed state transitions, hidden-information leaks, and cosmetic use of gameplay randomness. Inspect the final result after edits, not just the original plan. Fix findings and rerun affected checks; a separate review pass does not require another agent.
6. **Report the outcome precisely.** Separate what was implemented, what was tested and its result, what remains untested or blocked, and whether anything was committed, pushed, merged, or published. Never claim more verification than the evidence supports. A blocked browser check remains open; source inspection does not turn it into a pass. Complete independent authorized work and record the remaining gap without bypassing tool restrictions.

## Implementation and validation

- For presentation and interaction changes, follow `DESIGN.md` and review the affected entries in `docs/design-audit.md`. Record source evidence separately from browser observations; keep untested checks explicit.
- Make focused changes. Avoid framework migrations, broad rewrites, and dependencies unrelated to the request.
- Trace every path affecting shared state: player, bots, manager, temporary worker, AI agent, pipeline, rollback, and client transitions.
- Update tutorial text, controls, descriptions, and README whenever behavior changes. Do not leave contradictory instructions.
- Preserve pause, sound controls, keyboard/touch interaction, and reduced-motion behavior.
- Mix levels are calibrated against the endings' boot chime (`FX_GAIN`, `MUSIC_VOL`): new sounds go through `tone`/`noiseBurst` on the sound-effect bus and only the boot chime, hard drive and stamp pass `raw:true`. A limiter on the master catches stacked alarms; don't lean on it for loudness.
- Cosmetic code never draws on `Math.random`: sound and music use `sndRand`, Mr Paperclip uses `clipRand`, and drawing uses none. Otherwise sounds (throttled by wall-clock time) and music (on its own timer) shift the game's rolls and seeded runs stop matching.
- Use meaningful deterministic regression checks for accounting and state transitions. Validate full JavaScript syntax.
- Run `tests/regression.html` (served over HTTP) before pushing `main`; it must read `PASS`. Add or update checks there when you change a rule it covers, instead of writing throwaway scripts.
- GitHub Actions runs syntax, PWA, regression, and the desktop and phone browser tests (`tests/e2e/`) on every pull request and on `main`. A pull request that changes the game also gets a balance comparison against `main` (`tests/balance/`); treat a ⚠️ there as a prompt to explain or rebalance, never as proof a difficulty is (un)winnable. After a merge, `tests/smoke/` checks the live site. Its screenshots are evidence of layout and state, not a substitute for playtesting input feel, motion over time, or real-iPhone behavior (silent switch, `navigator.audioSession`, Home Screen mode). Add a scene to `tests/e2e/scenes.mjs` when you add a screen or touch word.
- Test patching early/mid/late in a cycle; covered/uncovered expiry; incident completion; failed/successful cutover accounting; freeze duration/cooldown/charge use; and escalation pickup/return/relocation when relevant.
- Browser-playtest visual and input changes. Source inspection or syntax checks alone do not establish that a UI looks or plays correctly.
- Do not refresh or restart a user's active test run unnecessarily. Use a separate tab for your checks.
- Capture real screenshots from the branch being documented; do not fabricate gameplay states or describe unmerged features as main behavior.
- Report what changed, checks performed, and outstanding limitations. Clearly distinguish local commits, pushed commits, and merges.

## Communication

Infer intent from the game's teaching purpose and the user's latest corrections. If a clarification changes the model, correct it directly. Do not keep obsolete implementations merely because they were previously proposed. Ask only when a consequential ambiguity remains; otherwise implement the smallest coherent change and show how it matches the requested behavior.

### Hidden-server discovery
Hidden servers require investigation or an outage to reveal them; never reveal based on migration progress. The three handmade clients keep their designed hidden tiers; generated clients (4+) can roll any of the three tiers. Tier totals must match the actual servers. Asset Inventory speeds investigation instead of bypassing it. Temp workers advance an unknown rack's investigation by 10–75% once, and never complete it. Escalations can target hidden racks and their fires continue growing while hidden. Reveal on burnout before applying normal outage handling. License conditions on discovery can already be expired or near expiry; charge expired liability once and preserve the normal countdown for upcoming renewals.
